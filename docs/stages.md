# 평가 단계·자기평가·점수 계산 정책 (D-068, 2026-10-28)

> 이 문서의 규칙은 대화 요약이 바뀌어도 그대로 유지되는 **현재 기준**이다. 코드: `src/domain/progress.ts`(STAGE_OF_RULE·pathFor·selfApplies·appliedStages), `src/domain/cycle.ts`(setSelfEval·buildAssignments), `src/domain/stagesV8.ts`(데이터 변환), `src/domain/scoring.ts`.

## 1. 단계 번호는 평가 유형으로 고정

| 단계 | 평가 유형 | 평가자 → 대상 |
|---|---|---|
| 1 | 자기평가 | 본인 |
| 2 | 팀장평가 | 소속 팀장 → **사원** |
| 3 | 임원평가 | 담당 임원 → 팀장·사원 |

| 대상 직급 | 받는 단계 |
|---|---|
| 사원 | 1 · 2 · 3 |
| 팀장 | 1(선택) · 3 — 2단계 없음(표에는 작은 "—") |
| 임원 | 1(선택)만 — 2·3 없음 |

- 상향평가(사원 → 팀장 등)는 없다.
- 평가자 배정 화면은 단계를 **켜고 끄기만** 한다. 번호를 다시 매기지 않으며, 반영 비율은 같은 번호를 따라간다. 같은 유형을 두 번 둘 수 없다.

### 1-1. 팀원→팀장평가 (D-114)

- 사원(평가자)이 **소속 팀의 현재 팀장**(대상자)을 평가한다. 1단계로 분류(배정 `stageOrder: 1`, `direction: 'up'`, 평가 유형 `upward`).
- 경로(path) 단계가 아니다 — **점수·단계 반영 비율·순차 잠금·임원평가 담당에 영향 없음**(D-103 직급별 최종 반영의 상향평가 40%도 적용 보류 그대로). 앞 단계를 기다리지 않고 바로 작성.
- 배정: 준비·진행 회차의 참여 사원 × 그 팀 현재 팀장(회차 참여자). 팀장이 없거나 참여하지 않으면 없음. 팀장·참여가 바뀌면 응답 없는 배정은 정리·새로 만들고, 응답 있는 배정은 `excluded: 'leadChanged'`로 보존.
- 평가표: 평가표 버전 **'팀원→팀장 평가표'**(공통 기본, 적용 평가 = 팀원→팀장평가) — 리더십·소통·업무 지원·공정성(5점 척도) + 의견(서술, 선택). 문항 관리에서 수정, 러시아어 번역 초안 포함.
- **D-187: 상향평가 = 팀원→팀장 + 팀원→임원 + 팀장→임원.** 참여 사원·팀장이 **소속 팀 임원**(이 회차 참여 임원, 팀마다 한 명 D-110)도 평가 — 같은 평가표·같은 규칙(1단계 분류, 점수·순차 잠금 밖). 임원 상향평가 점수 = 사원·팀장 평가의 평균(차장 답변, 점수 반영은 아직). 회차 표시 `upwardToExec`(v26 변환·새 회차에서 켬). 임원은 대상자 명단에 없어도 상향평가를 받는다(참여 변경 때 지우지 않음). 진행 현황 열 이름 **'상향평가'** — 칸 = 본인이 작성할 건 + 받는 건(사원 2건, 팀장 받는 건 + 1건, 임원 받는 건), 상세에 종류(팀원→팀장·팀원→임원·팀장→임원)를 함께 표시.
- **D-189: 평가표** — 팀원→팀장 = '팀원→팀장 평가표'(모두에게 동일 적용), 팀원·팀장→임원 = **'임원 상향평가표'**(직접 선택: 참여 임원 4명 체크 — 임원은 대상자 명단에 없을 수 있어 직급이 아니라 사람으로). 같은 영역·배점(회사 '임원 및 팀장 상향평가 예시'), 의견 문항만 '임원에게 바라는 점'. 새로 들어온 임원은 문항 관리에서 체크해야 이 평가표가 쓰임.
- **D-188: 상향평가는 1·2·3단계와 별개** — 화면에 단계 번호를 붙이지 않는다(상세·작성 화면·평가자 배정). 그 밖의 1·2·3단계 번호는 남색 글씨로 표시.
- 화면: 팀원 '내 평가'의 **상향평가** 목록(이전 '팀장 평가') → 작성·임시저장·제출 / 진행 현황 '팀원→팀장평가' 열(사원 = 작성할 1건, 팀장 = 받은 건수 x/y, 임원 —) — 완료자는 이것까지 제출해야 / 상세: 팀장 = 평가 현황·단계별 응답, 사원 = 담당 평가 현황 / 평가자 배정 화면 팀장 경로에 안내 행.
- 열람: 응답은 관리자 상세에서만. 평가받는 팀장·임원 화면에는 보이지 않음(목업 화면 제한 — 서버 보안 아님).

## 2. 순차 잠금

- 같은 대상자의 **앞 번호 중 실제로 있는 단계**가 모두 제출돼야 다음 단계가 열린다. 없는 단계(팀장의 2단계, 꺼진 자기평가)는 기다리지 않는다.
  - 사원: 1 → 2 → 3
  - 자기평가를 켠 팀장: 1 → 3, 끈 팀장: 3단계 바로
- 임원이 **평가자로서** 쓰는 3단계는 그 임원 본인의 자기평가 여부·제출과 무관하다.

## 3. 평가 참여·팀장·임원 자기평가 (회차별·직원별, D-072로 갱신)

- 위치: 평가 관리 → 평가 설정 → "평가 참여자" 카드(네 팀 + 임원). 줄마다 "참여" 체크 + 팀장·임원은 "자기평가" 스위치. 기본 정보와 함께 **저장 버튼으로** 저장(즉시 저장 아님).
- 참여: 사원·팀장 = 회차 대상자, 임원 = `execOff`에 없음(참여 임원만 새 배정의 평가자 후보). 다른 사람 평가 배정이나 받는 평가 응답이 있으면 참여 해제하지 않는다.
- 자기평가 스위치는 **현재 직급**이 팀장·임원인 사람에게만(D-077). 사원은 스위치 없이 자기평가 필수 — 이전 팀장 경로가 남은 현재 사원도 저장 시 켬.
- 참여와 자기평가는 독립: 자기평가를 꺼도 참여·평가자 배정은 그대로. 참여하지 않으면 자기평가 스위치는 비활성이고 값은 보존.


- **기본값: 팀장 켬, 임원 끔.** 사원은 항상 자기평가가 있다.
- 켜기: 임원이 회차 대상자가 아니면 대상자로 넣고 1단계 자기평가 배정을 만든다(꺼 두었던 응답 있는 배정이 있으면 그대로 되살림).
- 끄기: 응답이 없는 자기평가 배정은 지우고, 응답이 있으면 **지우지 않고** 제외 표시(`excluded: 'selfOff'`) — 진행·점수·작성 목록에서만 빠진다. 받는 평가가 하나도 남지 않은 임원은(응답이 없을 때) 대상자에서 빠진다.
- 확인창: 응답이 있는 자기평가를 끌 때, 3단계가 이미 시작된 사람의 자기평가를 켤 때.
- 확정된 회차는 바꿀 수 없다.

## 4. 진행 현황 집계 — 받는 평가 + 작성 업무 (D-076, D-071 대체)

| 열 | 사원 | 팀장 | 임원 |
|---|---|---|---|
| 자기평가(1) | 받는 상태 | 받는 상태(켰을 때, 끄면 —) | 받는 상태(켰을 때, 끄면 —) |
| 팀장평가(2) | 받는 상태 | **작성할** 사원 평가 건수 | — |
| 임원평가(3) | 받는 상태 | 받는 상태 | **작성할** 평가 건수 |

- 받는 상태: 제출 = ✓ 완료, 그 밖(미시작·작성 중·선행 대기·평가자 미지정) = 미완료, 적용 안 됨 = —. 작성 건수: "1/4 완료" + "3건 미완료"(모두 제출이면 초록), 배정 없으면 —.
- 직급은 현재 조직 기준. 직급과 맞지 않는 남은 작성 업무(이전 팀장 등)는 표 칸에 넣지 않고 업무 완료·미완료만·상세에 반영, 이름 옆 "배정 확인".
- 행 = 받는 평가 또는 작성 배정이 있는 재직 직원(직원 ID당 한 줄).
- 카드(사람 수, 필터와 무관): 평가 참여자 / 평가 업무 완료(받는 평가 + 작성 업무 모두 제출) / 1단계 = 자기평가 제출자÷자기평가 대상자 / 2단계 = 담당 사원 평가를 모두 쓴 현재 팀장÷배정된 팀장 / 3단계 = 담당 평가를 모두 쓴 임원÷배정된 임원.
- 카드 클릭: 1단계 = 자기평가 미제출자, 2단계 = 담당 팀장평가가 남은 팀장, 3단계 = 담당 임원평가가 남은 임원(다른 단계 조건 없음). 미완료만 = 단계 선택 중이면 그 기준, 아니면 받는 평가 또는 작성 업무가 하나라도 남은 사람.
- 상세: "받는 평가"(평가 유형·담당 평가자·상태, 배정 누락은 "평가자 미지정")와 "미완료 평가"(대상자·팀·평가 유형·미시작/작성 중/선행 단계 대기) + 작성할 평가 합계.

## 5. 점수 계산

- 기초 점수 = Σ(적용 단계 점수 × 반영 비율) ÷ Σ(적용 단계 반영 비율). 적용 단계 = 그 대상자에게 실제로 있는 단계(꺼진 자기평가 제외). 비율 합이 100이 아니어도 적용 단계 비율로 정규화한다.
- 기본 반영 비율(시드·새 회차 기준은 회차 설정 값): 사원 1:2:3 = 33.3:33.3:33.4, 팀장 1:3 = 50:50, 임원 1 = 100.
- 임원평가는 대상자당 담당 임원 한 명(D-082, 목업 구성 — D-081 전원 평가 대체). 참여 사원·팀장을 임원에게 팀 단위 우선으로 고르게 나누고, 관리자가 평가자 배정 화면에서 담당을 바꿀 수 있다. 단계 점수 = 담당 임원 응답.
- 미제출 단계가 있으면 계산하지 않음(0점 처리 없음). 이후 KPI 혼합·보정·최종 지정 순서는 `scoring.md` 그대로.

## 6. 직급

- 화면 직급은 **임원·팀장·사원**. 임원(대표자 포함) → 임원, 실제 팀장 연결 → 팀장, 나머지 → 사원. 직급 글자(반장·과장 등)로 판단하지 않는다.
- 팀장 직급은 팀 관리의 팀장 연결과 항상 일치한다. 다른 팀의 팀장을 조용히 덮어쓰지 않는다(확인 후 교체, 기존 팀장은 사원).
- 임원 직급은 운영 권한과 무관하다.

## 7. 저장 데이터 변환 v7 → v8

- 확정 전 회차: 팀장 경로의 임원평가를 2 → 3단계로, 그 배정의 `stageOrder`를 대상자 유형 기준으로 다시 매김(배정 ID·응답 그대로). 반영 비율도 같은 유형 번호로 이동. 임원 경로 추가(1단계, 비율 100). 기존 자기평가 상태(팀장: 활성 자기평가 배정 있음, 임원: 이전 D-056 제외 표시 → 끔)를 `selfEval`로 기록. 대상자 스냅샷 직급을 세 값으로.
- 확정 회차는 바꾸지 않는다. 직원 직급은 세 값으로 정리하고 대표자 표시는 임원으로 전환.
- 변환 전 데이터는 `daeyang-hr-mockup-v1-before-v8`에 보관. 다시 실행해도 바뀌는 것이 없다.

## 8. 목업 데이터 메모

- 임원 4명(홍성훈·김도현·박재원·전상철)은 가상 목업 데이터다. 임원을 모든 대상자에게 자동 배정하지 않으며, 임원 수 제한도 두지 않는다.
