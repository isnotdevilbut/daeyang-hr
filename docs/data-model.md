# 데이터 구조 초안

코드상의 정의는 `src/domain/types.ts`가 기준이다. 목업과 실서비스는 같은 타입(데이터 계약)을 쓰고, 저장 위치만 다르다(목업: localStorage / 실서비스: 서버 DB).

## 핵심 개념: 평가 방향 ≠ 진행 단계

- **평가 방향(Direction)**: 누가 누구를 평가하는가 — `self`(자기), `down`(상위자→대상자: 팀장평가·임원평가). `up`(팀원→팀장)은 후속 확인으로 미사용(D-011), 2022 원본 양식 보존용으로만 타입에 남김. 대표자 최종 확정은 평가 방향·단계가 아니라 결과 업무(Adjustment).
- **진행 단계(Stage)**: 순서 번호 — 1단계, 2단계, 3단계 … 각 단계에 방향과 평가자 규칙이 붙는다.
- 같은 "팀장평가"라도 경로에 따라 2단계일 수도 있고 없을 수도 있다. 2022 양식의 1차/2차/3차 열을 방향에 고정 대응시키지 않는다.
- 모든 배정은 단계 번호를 가진다(`stageOrder: number`). 팀장은 본인 자기평가 배정의 평가자이면서 팀원 하향평가 배정의 평가자일 수 있다.

## 진행 집계 단위

- 집계 대상 = 회차 대상자 스냅샷 중 현재 재직(활성)이고 평가 제외가 아닌 사람.
- 단계 상태(대상자별): 완료 / 작성 중 / 미시작 / 대기(앞 단계 미제출) / 평가자 미지정 / 해당 없음. 배정이 여럿이면 모두 제출해야 완료.
- 구현: `src/domain/progress.ts` (`cycleCounts`, `targetCells`, `pendingWork`).

## 유일성·무결성 규칙(실서비스에서 DB 제약으로 구현)

- 응답은 `Assignment` 당 1개. 같은 사람이 여러 정당한 평가(예: 팀장의 자기평가 + 팀원 평가)를 할 수 있도록 유일성은 회차·배정 기준.
- 평가자는 자기 자신을 후속 평가할 수 없다(자기평가 제외).
- 이력이 있는 직원·문항은 물리 삭제하지 않고 비활성화. 회차는 스냅샷을 쓰므로 팀 이동이 진행 중 회차를 덮어쓰지 않는다.
- 대표 지정값 0은 "값 없음"(null)과 다르다. KPI 미입력(null)과 0도 다르다.

## 보관·삭제 (미정)

"엑셀 보관 후 시스템 삭제" 희망이 있다. 다운로드 후 자동 삭제는 하지 않으며 보존 기간·백업·삭제 권한은 회사 확인 후 정한다.
